Why Agentic Reasoning Tracking > Task Completion
Audit quality depends on reasoning correctness, not output generation. An agent can "complete" a trial balance reconciliation but hallucinate a line item — a task-completion metric gives it 100% while it failed materially.
Independence risk: an agent citing the wrong standard (e.g., ISA-CH vs IFRS) may still complete its task. Only Hallucination Rate + SAT/TIRA compliance check catches this.
Auditor Trust Score (qualitative) is the final gate — even a technically perfect agent that auditors don't trust cannot be deployed. The Werchota approach captures this human signal.

Azure DevOps · Custom Fields Schema
ADO Work Item — Custom Field Definitions
These fields are the data bridge between MS Forms intake, Power BI Control Tower, and the KPMG Hexagon lifecycle.
KPMG Core Fields
KPMG_PriorityScore
Integer · Range 0–100 · Auto-calculated
Composite of the Initial Assessment Matrix: Business Value (0-30) + Strategic Alignment (0-20) + Suitability (0-20) + Feasibility (0-15) + Reusability (0-15). Scores are entered by Katarina Naldi / BA team post-assessment. Threshold gates: Accept ≥70, Park 50-69, Reject <50.
Accept: ≥70 Park: 50-69 Reject: <50
KPMG_BusinessValue
Integer · Range 0–30 · Manual (BA review)
Sub-score feeding into KPMG_PriorityScore. Set during Assess stage by Stallinger/Hasal. Value of 30 = material, recurring, multi-team or compliance-relevant impact.
KPMG_StrategicAlignment
Integer · Range 0–20 · Manual (PM + Stream Lead)
Assessed by Katarina Naldi + Svenja Hefti. 0 = out of scope → auto-reject regardless of total score. 20 = strong alignment with current WFM priorities.
0 = Auto-reject 20 = Strong alignment
Dev_Phase
Enum · Aligned to KPMG Hexagon
Maps directly to the 6 hexagon stages. Used in Power BI Views A and D for funnel and sprint filtering. Updated by Engineering Manager (Stefan Petrovic) at each sprint planning.
Identify Assess Prioritize Deliver Train Review
Audit_Independence_Check
Boolean · Default: FALSE · Set by Nicolas Vogt
Must be TRUE before any agent can move to Deliver stage when processing client data. Nicolas Vogt (Solution Architect) validates SAT/TIRA compliance and sets this field. If client data flag was set in MS Forms, this starts as FALSE and blocks Dev_Phase advancement.
TRUE = SAT/TIRA clear FALSE = Blocked
Werchota Enhancement Fields
Werchota_Complexity
Enum: Low / Medium / High · Set from MS Forms LLM field
Maps LLM orchestration needs to dev resource allocation. HIGH = requires both Skora + Gopurathingal + Nicolas Vogt architecture review. LOW = single developer sprint item. Used in Sprint Planning (Monday Afternoon) for capacity allocation.
Low = single LLM Med = RAG / multi-step High = multi-agent
Werchota_HITL_Ratio
Decimal 0.0–1.0 · From MS Forms slider → updated in Review
Planned HITL ratio from intake. Updated with actual ratio post-deployment in Review stage. Drives Suitability scoring cap. Power BI View B uses this field for the HITL scatter chart.
Werchota_AgentAccuracy
Decimal 0–100% · Set during Review stage · RAGAS eval
Populated by dev team during Review using automated evaluation against the Golden Dataset (linked in Werchota_GoldenDatasetLink). Agent must achieve >90% to exit Review. Tracked per sprint for regression detection.
Gate: >90% to exit Review
Werchota_HallucinationRate
Decimal 0–100% · RAGAS / custom eval · Review stage
Measured using RAGAS faithfulness + answer relevancy metrics. Target <3% for audit-facing agents. Agents with standard references (ISA-CH, IFRS) get additional grounding tests. Trend tracked sprint-over-sprint in Power BI.
Target: <3% Warn: 3-8% Block: >8%
Werchota_AuditorTrustScore
Decimal 0–10 · Qualitative survey · n = auditor respondents
Collected via quarterly MS Forms survey sent to Business Representatives (Anita Benz, Matthias Bachmann, Silvia Berchtold, Sven Waldenmaier, etc.). Average of 5 sub-dimensions: Accuracy trust, Explanation quality, Error communication, Time savings felt, Would recommend. Score <6.0 triggers Review despite passing technical checks.
Gate: >6.5 Target: >8.0
Werchota_GoldenDatasetLink
URL · Sharepoint / ADO artifact link
Link to the anonymized test dataset used for accuracy evaluation. Must be populated before Dev_Phase can move to Review. Lucie Hasal / Sebastian Stallinger responsible for dataset creation during BA phase.
